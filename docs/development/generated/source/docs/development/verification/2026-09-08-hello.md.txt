# 2026-09-08 HELLO·Mach 시간 초과 검증

기존 UI/UX와 DSP 처리값은 변경하지 않았습니다. 이전 문서화 이후 작업 트리에서 연결 경계를 확인했습니다.
운영 중인 엔진을 대신 실행하거나 시스템 오디오·설치된 드라이버 설정을 변경하지 않았습니다.

## 재현한 문제

1. C++ HELLO는 잘린 형식, 잘못된 ID·채널·샘플레이트·레이아웃·샘플 형식·용량을 정상 응답처럼 처리했습니다.
   C 드라이버에도 ID·예상하지 않은 header 권한 검사가 빠져 있었습니다.
2. C++는 매핑 실패 전에 출력 형식과 rate 인자를 덮어썼고, 실패한 매핑 또는 여러 descriptor의 권한을 남겼습니다.
   일부만 도착한 rate 목록에서는 Mach trailer가 데이터로 읽혔습니다.
3. 엔진 HELLO 분기는 요청을 검증하기 전에 기존 링과 수명주기 상태를 변경했습니다.
   협상 함수를 분리해 검증이 성공해야 기존 처리로 진입하도록 바꿨습니다.
4. 가득 찬 큐에 요청을 보내다 시간 초과되면 커널의 pseudo-receive로 복사된 서비스 권한과
   응답용 권한이 반환됩니다. 기존 HELLO·C/C++ 생존 확인·일반 제어 경로가 이를 정리하지 않았습니다.

초기 HELLO 검사에서 **47개 검증 항목이 실패**했습니다. 이후 별도로 추가한 시간 초과 스트레스는
C++ 생존 확인·C 드라이버 생존 확인·일반 제어 요청 각각에서 10회 실패 뒤 서비스 참조 11개,
임시 권한 10개 증가를 관찰했습니다. 원래 호출자가 소유한 서비스 참조는 1개입니다.

## 변경한 경계

- `shared/protocol/roomcut_handshake.h`: HELLO 요청·응답·협상 결과의 C 호환 유효성 검사.
- `engine/src/Handshake.cpp`, `engine/include/Handshake.hpp`: `engineNegotiateHello`로 검증과 기존 협상 정책을 분리.
  C++ HELLO에 송수신 각각 기본 1000ms 제한을 적용하며 기존 호출은 기본 인자로 유지합니다.
  완성된 임시 매핑이 검증된 뒤에만 호출자의 기존 매핑·출력 인자를 교체합니다.
- `engine/src/main.cpp`: HELLO 검증 후에만 상태 변경·기존 링 해제에 진입하고 초기 생성 실패의 응답 권한을 정리합니다.
- `engine/src/RingRegion.cpp`, `engine/include/RingRegion.hpp`: 협상한 크기만 매핑하는 경로와 실제 헤더의 일치 검사.
  기존 일반 매핑 API는 헤더를 읽은 뒤 같은 검증 경로로 진행합니다. 권한은 성공했을 때만 가져갑니다.
- `driver/RoomcutHAL/src/RoomcutTransport.c`: 같은 HELLO 응답 검증과 실패 권한 정리를 사용합니다.
- `shared/protocol/roomcut_mach_cleanup.h`: 복구 가능한 send 오류의 반환 권한을 정리하는 공통 함수.
- `engine/src/Heartbeat.cpp`, `engine/src/Control.cpp`: 실제 누수가 재현된 생존 확인·제어 요청에 공통 정리를 연결합니다.
- `engine/tests/test_handshake_validation.cpp`, `engine/tests/test_mach_cleanup.cpp`, `core/tests/CMakeLists.txt`: 실제 통신 회귀 검사.

단순 메시지에서 권한 해제를 임의로 추정하지 않았습니다. Apple의
[메시지·시간 초과 설명](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/osfmk/man/mach_msg.html)과
[libsyscall 정리 코드](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/libsyscall/mach/mach_msg.c)를 확인하고,
실제 반환 헤더의 remote/local 권한 종류와 참조 수를 측정했습니다.

## 실제 검증 범위

- 18가지 응답 조건을 C 드라이버·C++ 신규 연결·C++ 기존 매핑이 있는 재연결에서 각각 실행했습니다.
  정상·구버전·부분 rate 목록, 필수 형식 누락, ID·타입·상태 오류, 잘못된 형식, 헤더 불일치,
  잘못된 링 magic, 메모리 크기 부족, 추가 권한, 여러 descriptor, 메모리가 아닌 포트를 포함합니다.
- 정상 응답과 구버전 응답 모두 같은 물리 페이지에 실제 float32 프레임을 쓰고 읽어 정확한 일치를 확인했습니다.
- 9가지 요청 조건: 정상, 잘림, 잘못된 ID·타입, 버전 0·미지원 버전, 잘못된 응답 권한 종류,
  응답 포트 누락, 복합 메시지. 실제 수신 메시지를 생산 코드의 협상/응답 함수에 전달했습니다.
- 9가지 샘플레이트·용량 사례로 기존 48kHz 대체값, 고샘플레이트의 약 85ms 링 정책,
  지원하지 않는 선호 형식의 stereo float32 협상과 스케줄링 힌트 보존을 확인했습니다.
- 무응답과 가득 찬 큐에서 C/C++ HELLO의 시간 제한과 권한 정리를 확인했습니다.
- C++ 생존 확인·C 드라이버 생존 확인·일반 제어 요청은 각각 10회 연속 시간 초과 후
  **서비스 참조 1개, 임시 send-once/dead-name 권한 증가 0개**입니다.
- 상대가 취소한 뒤 send-once 응답을 보낼 때 이 환경의 커널은 성공을 반환하고 권한을 정리했습니다.
  처음 검사에서 특정 오류 반환을 예상했으나 실제 관찰에 맞게 수정했습니다. 반환 성공을 상대의 수신 증거로 사용하지 않습니다.

## 한계와 다음 작업

이 검사는 호스트 프로세스 안의 실제 Mach·공유 페이지·드라이버 C 함수·엔진 협상 함수를 검사합니다.
설치된 `coreaudiod`와 운영 엔진의 전체 수명주기, 실제 출력 장치·절전·청취 검사를 대신하지 않습니다.
커널 자원 고갈처럼 메시지가 부분 소멸할 수 있는 모든 오류를 강제로 재현한 것은 아닙니다.
DSP 계산 비용이나 전체 시스템 오디오 지연의 개선률은 이번 검사에서 주장하지 않습니다.

다음은 ARC-01의 장치 감시·볼륨 동기화 책임 분리입니다. 기존 장치 정책·복구·콜백 수명을 테스트로 고정한 뒤 이동합니다.
전체 God object 제거와 다이내믹 EQ·Room Tune·고샘플레이트 비용·실기기 검증 목표는 계속 활성 상태입니다.
