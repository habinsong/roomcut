# 2026-09-10 엔진 진입부의 진단·서비스 수명·급전 감시 분리

ARC-01의 남은 경계 중 진단(dev 캡처), 서비스 이름 수명, 드라이버 급전 감시를
진입부에서 떼어냈습니다. 동작은 그대로 두고 소유권과 검사 가능성만 바꿨습니다.
`engine/src/main.cpp`는 1126행에서 1014행이 됐습니다.

## 분리한 담당

| 담당 | 파일 | 책임 | 진입부에 남은 것 |
|---|---|---|---|
| 급전 감시 | `engine/include/DriverFeedWatchdog.hpp` | 쓰기 인덱스와 하트비트로 드라이버 상실/복귀 판정 | 판정에 따른 수명 상태 전이와 로그 |
| 진단 | `engine/include/EngineDiagnostics.hpp`, `engine/src/EngineDiagnostics.cpp` | `--dump`/`--eq` 해석과 float32 WAV 기록 | 캡처 버퍼 할당과 종료 시 기록 호출 |
| 서비스 수명 | `engine/include/ServicePort.hpp`, `engine/src/ServicePort.cpp` | 이름 확보(launchd 체크인 → dev 등록)와 우리가 만든 권한만 반환 | 메시지 수신 루프 |

## 검사

새 네이티브 검사 3개로 CTest는 37개에서 40개가 됐습니다.

- `driver_feed`: 하트비트가 살아 있는 60초 무음은 상실이 아니고, 급전 정지와 하트비트
  침묵이 함께일 때만 1회 상실을 보고하며, 복귀도 1회만 보고합니다. 하트비트만으로는
  정지가 풀리지 않고, 복귀 뒤 다시 정지하면 새로 보고합니다.
- `engine_diagnostics`: 인자 없음/양쪽 플래그/짧거나 긴 EQ 목록·비숫자·값 없는 플래그·
  알 수 없는 플래그를 검사하고, 기록한 WAV의 헤더(형식 3, 32비트, 채널·샘플레이트·
  데이터 크기)와 샘플 왕복, 쓸 수 없는 경로의 실패를 확인합니다.
- `service_port`: 확보한 이름을 다른 곳에서 조회해 실제 Mach 메시지를 보내고 서비스
  포트에서 받습니다. 우리가 만든 권한은 반환되고, launchd가 넘겨준 권한은 건드리지
  않으며, 두 번 반환해도 달라지지 않습니다.

## 실행 결과

- CTest 40/40, Swift XCTest 218/218 통과.
- 재빌드한 엔진을 3초간 직접 실행해 인자 해석·서비스 확보·시작 복구 경로를 확인하고
  SIGTERM으로 종료했습니다. 잘못된 인자는 종료값 2와 사용법을 출력합니다.

## 한계

- 이 세션에서는 `bootstrap_check_in`이 항상 성공해 dev 등록 경로는 실행되지 않았습니다.
  검사는 두 경로를 모두 허용하고 관측된 경로에 맞는 조건만 확인합니다.
- 라우팅 IO 조율(장치 선택·재개방 순서)은 여전히 진입부에 있습니다. ARC-01은 열린 상태입니다.
- 직접 실행 중 이 Mac의 기본 출력이 잠시 Roomcut에서 iFi로 바뀌었다가 실행 중인 앱이
  다시 Roomcut으로 되돌렸습니다. 확인 시점의 기본 출력은 Roomcut Output입니다.
