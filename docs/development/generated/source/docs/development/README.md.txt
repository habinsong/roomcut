# Roomcut 개발 문서

기준: 2026-09-09. 기존 감상 중심 UI/UX, 탭 구성, 유리 효과와 디자인 토큰을 유지합니다.
목표는 지속 개발이며, 테스트 통과나 이번 작업의 완료를 전체 제품의 완성으로 취급하지 않습니다.

이미 실행 중인 엔진에 실제 UI를 연결하는 진단 실행은 `open -n build/Roomcut.app --args --attach-engine`입니다.
이 모드는 서비스 시작/종료를 하지 않으며 UI 조작은 실제 엔진에 반영됩니다. 검사 전 설정을 보존하고 복구를 확인합니다.

## 전체 구현 기록의 범위

Git 추적 파일과 Git에서 무시하지 않는 미추적 파일을 현재 디스크 내용으로 기록합니다.
소스, 테스트, 빌드 설정, CI, 스크립트, 스키마, 기존 문서, 로컬 `AGENTS.md`가 대상입니다.
텍스트 파일은 `generated/source/<원래 경로>.txt`에 요약이나 생략 없이 바이트 그대로 보존합니다.
이미지 등 바이너리는 원본 링크·크기·해시로 기록합니다. 구현 원본이 편집의 기준입니다.

빌드 산출물·패키지 캐시·Git 내부 자료는 구현 소스가 아니므로 목록에서 제외합니다.
비밀 파일은 읽거나 복제하지 않습니다. 생성 문서 자신은 재귀 복사를 막기 위해 제외합니다.
이 범위와 제외 규칙은 생성기와 전체 목록 첫머리에도 명시합니다. 심볼릭 링크는 자동 추적하지 않고 오류로 알립니다.

```bash
python3 scripts/update-development-docs.py
python3 scripts/update-development-docs.py --check
```

새 파일의 추가, 내용 변경, 삭제, 보관 원문의 손상 모두 `--check`가 실패로 감지합니다.
수동 문서나 증거 자료를 갱신한 뒤에도 위 두 명령을 실행합니다. 생성 폴더 안에 수동 문서를 작성하지 않습니다.

## 지속 작업 순서

1. `git status --short`와 현재 이슈를 확인하고 진행 중인 변경을 보존합니다.
2. 가장 높은 우선순위의 독립적인 작업 하나를 고릅니다. 증상이 불분명하면 먼저 재현합니다.
3. 관련 공식 웹 문서를 다시 열고 확인일·적용 범위·출처를 갱신합니다. 열지 못한 자료를 검증된 근거로 쓰지 않습니다.
4. 현재 코드의 책임 경계를 읽고 최소 수정합니다. 새 기능의 기본값은 기존 동작을 유지합니다.
5. 실패 재현 검사 → 수정 후 동일 검사 → 관련 전체 검사 순서로 수행합니다.
6. 실제 결과와 원시 자료를 검증 폴더에 기록하고 이슈·계획·전체 구현 원문을 갱신합니다.
7. 다음 작업 하나를 남깁니다. 관찰하지 않은 하드웨어 동작이나 청취 품질은 성공으로 적지 않습니다.

현재 작업에 매시간 이어서 실행하는 자동화 `roomcut`을 등록했습니다.
의미 있는 완료·실패·사용자 조치가 있을 때 알리도록 설정했습니다.
로컬 실행에는 컴퓨터가 켜져 있고 앱이 실행 중이어야 하며, 사용 한도와 도구 가용성의 영향을 받습니다.
[OpenAI의 예약 작업 안내](https://learn.chatgpt.com/docs/automations?surface=app)를 2026-09-08 확인했습니다.

커밋·푸시·배포·드라이버 설치·시스템 오디오 변경은 이번 문서화/자동화 설정으로 수행하지 않습니다.
