# 지속 개발 계획

`1.0.9`의 로컬 빌드와 패키지 확인은 끝났지만, 이 계획의 실기기·설치·성능 항목은 계속 남아 있습니다.
범위와 결과는 [2026-09-09 릴리스 검증 기록](../verification/2026-09-09-release.md)을 참고합니다.

## 제품 기준

기존 감상 중심 화면, 탭, Basic/Advanced 흐름, 디자인 토큰과 키보드 접근성을 유지합니다.
새 기능은 필요한 위치에 선택적으로 노출합니다. 음질·속도·기능의 우수성은 측정 가능한 기준으로 판단합니다.
외부 제품의 화면을 복사하거나, 추측을 근거로 오디오 경로를 바꾸지 않습니다.
사용자의 추가 목표에 따라 실제 앱 빌드·조작과 사운드 체크를 지속 QA에 포함합니다.
각 담당의 책임을 유지하며 God object에 새 기능이나 QA 제어를 누적하지 않습니다.
실제 출력/설정은 검사 전에 읽고 필요한 변경을 마친 뒤 복구를 확인합니다.

## 우선순위별 실행 단위

| 순서 | 목표 | 최소 작업 | 통과 조건 |
|---|---|---|---|
| 1 | 현재 이슈와 구현을 빠짐없이 추적 | 전체 파일 목록·원문·웹 출처·검증 자료·현재 이슈 작성 | 생성기 `--check`, 추가/수정/삭제 누락 검출, 실제 테스트 기준선 |
| 2 | 생존 확인 통신 오류 해결 | IPC-01의 길이·ID·상태·권한 검증 | 잘못된 응답 거부, 구버전 수락, 포트 참조 누수 없음 |
| 3 | 연결 초기화 경계 감사 | HELLO의 요청/응답 크기·버전·descriptor·매핑 소유권 | 실제 Mach 실패 행렬, 기존 정상/구버전 핸드오프 유지 |
| 4 | 엔진 책임 분리 | 장치 감시/볼륨 → 복구 조율 → 서비스 명령 순서 | 각 소유권 명확, 모의 HAL·IPC·신호 검사 동일, 새 렌더 할당 없음 |
| 5 | 앱 책임 분리 | 폴링과 장치 상태를 편집 모델에서 분리 | 장치 전환·연속 편집·늦은 응답·연결 실패·Undo 유지 |
| 6 | Room Tune 신뢰도 | PCM 입력·클록 편차·노이즈·취소·실패 보강 | 신호별 허용 오차와 거부 조건 명시, 메인 스레드 정지 없음 |
| 7 | 선택적 다이내믹 EQ | 한 밴드의 수동 임계값·범위·attack/release부터 DSP와 테스트 구축 | 아래 기능 기준 통과 후 기존 Advanced 흐름에 연결 |
| 8 | 진단과 청취 도구 | 전체 지연 구성 표시, 비교 준비 상태/헤드룸의 정확한 설명 검토 | 보고 값과 실제 임펄스/레벨 측정의 관계 검증 |
| 9 | 품질을 유지하는 최적화 | DSP 전환·레벨 비교·리샘플링의 상위 비용부터 측정 | 동일 입력의 출력 허용 오차, 평균/p99/최대·할당·메모리 비교 |
| 10 | 실제 환경 검증과 배포 준비 | 장치/샘플레이트/절전/재연결/설치 행렬 | 실제 실행 증거, 남은 제한 기록; 공개 배포는 별도 지시 |

각 순서는 한 번에 모두 수정하라는 뜻이 아닙니다. 재현된 더 심각한 문제가 생기면 우선순위를 올리고 이유를 기록합니다.
한 항목을 마칠 때마다 이슈·계획·전체 원문을 갱신하고 다음 항목으로 이어갑니다.
실제 앱/사운드 QA는 마지막 배포 단계만의 작업이 아닙니다. 기능별로 실행하되 최신 앱·설치 엔진·새 엔진·모의 HAL·실기기·녹음/청취 근거를 구분합니다.

## 레퍼런스로 구체화한 기능 후보

### 선택적 다이내믹 EQ

목적은 특정 대역이 커질 때만 필요한 만큼 줄이는 조작입니다. 이미 있는 그래픽 EQ를 자동으로 바꾸지 않습니다.
첫 단계는 파라메트릭 벨 밴드 하나, 수동 임계값, 최대 감쇠 범위, attack/release, 좌우 연동으로 제한합니다.
자동 임계값, 외부 사이드체인, 스펙트럴 모드, AI 제안은 반복 사용 필요와 측정 근거가 생긴 뒤 별도 평가합니다.

참고: [FabFilter 동적 EQ 사용 흐름](https://www.fabfilter.com/help/pro-q/using/dynamic-eq),
[W3C Audio EQ Cookbook](https://webaudio.github.io/Audio-EQ-Cookbook/audio-eq-cookbook.html).
구체 DSP 알고리즘과 시간 상수는 Roomcut의 설계 선택이며 외부 제품과 같다고 주장하지 않습니다.

구현 전 검증 계약:

- 기능을 끄면 기존 정적 EQ의 출력·지연·파라미터 직렬화가 유지됩니다.
- 임계값 아래/위의 사인·멀티톤·버스트에 대한 동작, 감쇠 한도, 좌우 일치를 수치로 검사합니다.
- 공격/복귀 구간, 무음에서의 복귀, 파라미터 변경과 우회의 클릭·과도 출력·NaN을 검사합니다.
- 44.1/48/96/192kHz와 실제 지원 상한, 블록 분할에 따른 출력 차이를 검사합니다.
- 오디오 스레드의 할당·잠금·파일 I/O가 없고 기능을 끈 비용이 늘지 않는지 측정합니다.
- C 메시지의 호환성과 capability, 프리셋·A/B·Undo·UI 상태를 함께 검증한 뒤 사용 가능 상태로 표시합니다.

### 지연과 비교 상태의 정확한 안내

이미 있는 A/B·레벨 비교에 이어 링 대기, 리샘플러, 리미터, HAL의 지연을 각각 조사합니다.
알려진 DSP 지연과 전체 시스템 지연을 같은 수치로 표현하지 않습니다. 임펄스와 실제 왕복 측정을 구분합니다.
실측 근거가 확보되기 전에는 추정치를 확정된 지연으로 표시하지 않습니다.

### Room Tune 결과 신뢰도

현재 측정 흐름 안에서 녹음 포화·잡음·지연·반복 측정 불일치의 거부/재측정 조건을 개선합니다.
[REW 측정 안내](https://www.roomeqwizard.com/help/help_en-GB/html/makingmeasurements.html)의 시간 기준과
클록 차이 고려를 참고하며, 마이크 보정 없이 얻은 결과를 절대적인 실내 응답이라고 단정하지 않습니다.

## 최적화 방법

최적화 전후를 같은 컴파일러·Release 옵션·신호·블록 크기·준비 구간으로 번갈아 실행합니다.
평균뿐 아니라 p99와 최대 블록 시간, CPU 시간, 메모리, 렌더 할당을 기록합니다.
필터 품질을 낮추거나 검사 허용 오차를 넓히는 방식으로 속도 향상을 주장하지 않습니다.
합성 벤치마크와 실시간 HAL의 스케줄링·글리치·청취 결과는 따로 기록합니다.

## 다음 시작점

IPC-02와 파생된 IPC-03의 실제 Mach 회귀 검증을 마쳤습니다.
ARC-01의 장치 감시·볼륨 동기화 분리는 호스트·계측 검사와 실제 CoreAudio 등록/해제 확인을 마쳤습니다.
출력 재시도 정책과 렌더 속도 감시도 분리하고, 시작 실패·시간 제한·장치 변경 회귀를 검증했습니다.
음색 명령 해석·응답 조립·저장 데이터 변환을 분리하고, 기존 응답 1024회 비교와 실제 Mach·저장 왕복을 검증했습니다.
저장 시 소수점 반올림으로 설정을 잃는 문제도 수정했습니다.
ARC-02의 폴링 수명과 장치 읽기를 분리하고, 중단·재시작·늦은 응답·조회 중 편집을 검증했습니다.
장치 쓰기는 전용 큐와 순서 담당으로 분리했고, ON/OFF 역전·이전 오류·외부 증폭 해제 표시를 수정했습니다.
느린 장치 읽기는 상태/미터 갱신과 독립적으로 처리하며, 한 건 진행·최신 한 건 대기와 중단/전환 시 무효화를 검증했습니다.
IO-01의 볼륨 쓰기는 증폭 거절·실장치·가상장치·음소거 해제 실패가 성공으로 숨겨지는 문제를 수정했습니다.
실제 C 진입점과 Mach, 모의 HAL로 단계별 실패와 기존 소프트웨어 볼륨 경로를 검사했습니다.
IO-02도 기본 출력의 이미 적용됨 반환값·형식 변경 실패·밸런스 입력/무음/출력 소실을 재현해 수정했습니다.
ARC-04의 클라이언트 장치 접근을 `CoreAudioDevices`로 분리했습니다. 장치 모듈은 엔진 조회나 연결 캐시를
소유하지 않습니다. C 헤더·24개 공개 심볼, 기존 함수 본문, 분리 전후 C/Mach·모의 HAL 검사 결과를 비교했습니다.
RT-01에서 PCM 변환 결함 RT-02를 재현해 수정했습니다. 실제 CMSampleBuffer 형식/배치 24조합,
WAV 형식/샘플레이트 24조합, 평탄 응답의 클록 ±1000ppm·SNR 20/40dB를 검증했습니다.
RT-03에서 측정 순서·회차 정리·네이티브 미디어 작업을 분리하고 늦은 완료·취소·복구 누락을 재현해 수정했습니다.
앱이 측정 객체 하나를 소유하며 정리 완료 후 다음 측정을 허용합니다. Swift/TSan과 평가용 UI의 탭 이동·정상 완료·진행 중 종료를 확인했습니다.
RT-04의 최신 직접 선택을 덮어쓰는 문제는 쓰기/임시 복구 소유권으로 수정하고 요청 추적·UI로 확인했습니다.
`--attach-engine`으로 최신 앱을 설치 엔진의 iFi 384kHz·24-bit 경로에 연결해 실제 검사음을 재생했습니다.
처리/우회 피크와 언더런 증가 0을 확인하고 원래 EQ·PEQ·볼륨·출력·처리 상태를 보존/복구했습니다.
RT-05의 캡처 중단·재생 완료 누락·기한 뒤 완료 콜백·느린 정지를 제어 가능한 전송으로 검사하고,
녹음이 남지 않은 회차가 내부 오류 문자열을 표시하던 문제를 수정했습니다.
ARC-01의 진단·서비스 수명·드라이버 급전 감시를 각각 분리하고 네이티브 검사 3개를 추가했습니다.
PERF-01을 재측정해 이전의 p99 초과가 재현되지 않음을 확인하고 기준선을 남겼습니다.
EQ-01을 DSP부터 UI까지 연결했습니다. 끈 상태의 출력·비용이 그대로임을 확인했고, 실제 앱 조작은 남았습니다.
ARC-01의 출력 재개방 순서를 `OutputRouter`로 분리하고 순서 검사를 추가했습니다.
계획 8번의 지연 표시는 임펄스 측정과 대조해 엔진이 더하는 지연만 따로 보고합니다.
다음은 ARC-02의 남은 상태 적용 조율, 이어서 ARC-03(Now Playing)입니다.
새 엔진 바이너리의 실기기 검증은 설치 엔진에서 얻은 결과와 별도로 남아 있습니다.
실제 마이크/AGC·장치 소실·권한 UI와 합성 버퍼/파일 검사는 계속 구분합니다.
기존 화면·편집 이력·A/B 동작은 유지합니다.
ARC-01의 남은 진단/서비스 수명, Room Tune 입력 신뢰도, 선택적 다이내믹 EQ, 고샘플레이트 비용 측정도 계속 추적합니다.
