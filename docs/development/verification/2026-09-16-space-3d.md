# 2026-09-16 Space 3D 그림 재작성

## 변경

기존 그림은 청취자가 카드 하단에 있는데 장면 전체를 `-headYaw * 0.35`만큼 회전했다.
유리 스피커 표면이 회전 중 커져 겹쳤고 후방 채널은 카드 밖으로 빠졌다.
사용자 요청에 따라 그림 영역을 실제 SceneKit 3D 장면으로 전면 재작성했다.

- `SpatialFieldView.swift`: 기존 파라미터 연결, 상태 설명, 접근성, `SCNView` 연결.
- `SpatialFieldScene.swift`: 고정 원근 카메라, 입체 방·스피커·청취자·음장 곡면.
- `Package.swift`: 새 장면 파일을 앱 타깃 소스에 추가하고 공유 타깃에서 제외.
- `scripts/check-spatial-field.swift`: 센서·엔진 없이 실제 장면을 렌더하고 회귀 검사.

방과 채널 위치는 고정한다. 양수 yaw일 때 머리·헤드폰·방향 화살표가 오른쪽으로 돌아간다.
좌표계가 바뀌었기 때문에 SceneKit Y축에는 `-yaw`를 적용한다. 화면 좌우는 실제 투영으로 검사했다.
±180°는 직접 3D 변환하며 각도에 스프링 보간을 적용하지 않는다.

Space는 음장 곡면 폭, Center는 중앙 집중 영역, Damping은 패널과 원음 확산 윤곽을 바꾼다.
헤드폰 5.1/7.1은 C·L·R 스피커와 측·후방 확산 채널을 표시한다. 스피커 Wide에는 후방과 C를 만들지 않는다.
Center Width·Surround Depth·Room 종류·Amount·Balance도 각각 반영한다.
헤드폰 업믹스·트래킹 중 무시되는 Crossfeed는 표시하지 않는다.

카드·세그먼트·슬라이더 동작과 DSP·IPC·실제 장치 설정은 변경하지 않았다.
타이머·상시 렌더링·SCNActions·오브젝트 유리 효과는 없다. yaw만 바뀌면 머리 노드 하나만 갱신한다.

3D 검사에는 -180°…+180° 361방향의 실제 머리 전방 벡터, ±179° 경계,
트래킹 Off·스피커 모드의 회전 무시, 5.1/7.1 채널, 룸/바닥의 화면 경계가 포함된다.
같은 설정은 재렌더 요청을 만들지 않고, yaw 변경은 머리 지오메트리를 다시 만들지 않는다.
361회 yaw CPU 장면 갱신은 이 실행에서 1.415 ms였다. GPU 프레임 시간이나 장시간 사용률 측정이 아니다.

이미지 비교는 같은 효과의 숨겨진 Crossfeed가 장면을 바꾸지 않는 경우 2건과
각 설정이 장면을 바꾸는 경우 36건이다. 픽셀 비교 최초의 완전 동일 기준은
SceneKit 경계·그림자 래스터화에서 일부 픽셀 최대 5/255 차이로 실패했다.
실제 효과 차이와 구분하기 위해 8/255 초과 픽셀을 비교했고 숨겨진 효과는 0픽셀,
활성 설정 변화는 각각 100픽셀 이상임을 확인했다.

네이티브 앱 검사는 실제 `SpaceTab`과 최종 장면 구현을 사용하는 별도 검증 호스트에서 수행했다.
메모리 엔진 클라이언트를 사용해 실제 오디오·기본 출력·센서·사용자 프리셋에는 쓰지 않았다.
슬라이더의 직접 값 설정은 접근성 API가 지원하지 않아 Increment 동작으로 Space 0 → 40을 확인했다.
이후 채널 글자·머리 크기·방향 화살표 높이를 조정하고 56장 렌더 검사를 다시 통과했다.
