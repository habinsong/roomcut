## 완료 기준과 순서

1. **기존 문제 해결**: 무음 복구, 최종 출력 보호, 리미터 설정 반영,
   Room Tune 시간 정렬·입력 검증·녹음 수명주기, 장치 복구, IPC와 스레드
   경계를 실제 코드 경로로 회귀 검증합니다.
2. **책임 분리**: 엔진 쪽에서는 렌더와 장치 수명주기, 상태 저장, 명령 처리를,
   앱 쪽에서는 프리셋과 설정 저장, 기기 제어, 표시 상태를 각각 응집된 모듈로
   분리합니다. 파일만 나누거나 기존 God object에 새 책임을 추가하지 않습니다.
3. **EQ 품질**: 주파수 응답, 프리셋 전환 연속성, 샘플레이트 변환,
   최종 레벨 보호, 채널 일관성과 지연을 신호로 검증합니다.
4. **새 기능**: 기존 조작 체계 안에서 A/B 비교·실행 취소/다시 실행,
   레벨을 맞춘 비교, 선택적 다이내믹 EQ를 순차 구현·검증합니다.
   이 목록은 첫 구체화이며 기존 기능 안정화와 함께 계속 평가합니다.
5. **자료 기반 개선**: 공식 문서와 측정 자료를 변경 근거에 연결합니다.
   기능을 모방하기 위한 UI 재설계나 불필요한 의존성 추가는 하지 않습니다.
6. **성능·품질·속도**: 최적화 빌드에서 콜백 처리 시간·할당·CPU 비용,
   다양한 샘플레이트/블록 크기 및 무처리 투명성을 측정합니다.
   빠른 처리만으로 음질이나 실제 하드웨어 안정성을 말하지는 않습니다.

## 2026-09-07 검증 기록

- 실제 엔진이 사용하는 `RenderPipeline`과 `GainRamp`를 독립시켰습니다.
  무음이 유지되고 복구되는지, 좌우 페이드가 맞는지, 200% 증폭/바이패스에서
  최종 제한이 걸리는지를 보고 44.1~768kHz와 8192 프레임을 넘는 콜백,
  비정상 샘플, 리미터 복귀 시간도 함께 검사합니다.
- 파라미터 슬롯 소유권을 분리했고 20만 회 동시 갱신 테스트와
  ThreadSanitizer가 통과했습니다. 분석 버퍼와 장치 수명주기 검사는 아직 남았습니다.
- 렌더 테스트는 AddressSanitizer·UndefinedBehaviorSanitizer를 통과했고,
  준비 이후 렌더/파라미터 갱신의 C++ 힙 할당 검사는 0회입니다.
- Room Tune의 시간 구간 RMS를 테스트음 대비 전달 응답 분석으로 교체했습니다.
  0~500ms 지연의 500Hz 공진, 평탄 응답, 무음·클리핑·무관한 음·잘린 녹음,
  낮은 샘플레이트 파일 변환의 7개 테스트가 통과했습니다.
  실제 iPhone의 AGC·잡음·클록 오차·장치 연결 변화까지는 아직 보지 못했습니다.
- 측정 경로는 재생 완료와 후행 녹음을 기다리며, 분석을 메인 스레드 밖에서
  실행합니다. 화면에서 벗어나면 취소와 우회 복구, 임시 파일 정리를 진행합니다.
  실제 마이크 수명주기와 다양한 PCM 입력 형식 검증은 다음 단계로 남겨 두었습니다.
- 전체 God object 제거, 새 EQ 기능, 리샘플링 음질과 실기기 복구 검증은
  **미완료**입니다. 위 항목 통과를 전체 목표 완료로 취급하지 않습니다.

### 렌더 성능 비교

`HEAD`의 기존 콜백과 현재 콜백을 같은 `-O3` 조건에서 메모리 링에 연결해
비교했습니다. 실제 장치는 열지 않았습니다. 512 프레임 블록에서 충분한 준비
구간을 둔 뒤 10초 분량 신호를 7회 처리해 중앙값을 냈습니다. 전체 효과 조건은
그래픽/파라메트릭 EQ, 공간 처리, 하이패스와 컴프레서를 함께 켠 경우입니다.

| 샘플레이트 | 조건 | 이전 ns/프레임 | 변경 ns/프레임 |
|---|---|---:|---:|
| 48kHz | 평탄 | 52.680 | 49.477 |
| 48kHz | 전체 효과 | 189.455 | 185.641 |
| 192kHz | 평탄 | 49.664 | 48.809 |
| 192kHz | 전체 효과 | 200.946 | 196.887 |
| 384kHz | 평탄 | 47.563 | 45.653 |
| 384kHz | 전체 효과 | 199.480 | 195.481 |

이 측정은 콜백 계산 비용이며 실기기 지연, 시스템 전체 CPU, 글리치율을
대신하지 않습니다. 초기 짧은 준비 구간에서는 편차와 비용 증가가 관찰되어
정상 입력/100% 게인 경로의 반복을 줄이고 준비 구간을 늘려 재검증했습니다.
이 초기 비교의 원시 결과는 `build/render-benchmark-initial.csv`에 있습니다.

## 2026-09-07 후속 작업: 동시성·상태 저장

- `AnalysisTap`은 2048 프레임과 샘플레이트·세대를 하나의 완성된 스냅샷으로
  전달합니다. `AnalysisWorker`가 처리 주기와 결과 평활화를 맡습니다.
  샘플레이트가 같아도 재시작 세대가 바뀌면 이전 평활화 값을 섞지 않습니다.
- 기존 분석 코드에서 과거 구간의 레벨 0.1 대신 덮어쓴 구간의 0.8을 읽는
  상황을 재현했습니다. 기존 코드의 ThreadSanitizer 스트레스 두 번만으로는
  경고가 나오지 않았고, 지연된 스냅샷 복사를 직접 재현해 문제를 확인했습니다.
- `PublishedRing`은 실제 읽기 수명이 끝날 때까지 매핑 해제를 기다립니다.
  기존 20ms 대기를 제거했습니다. `RenderCallbackGate`는 세대 번호를 사용하고,
  진입한 콜백이 끝나기 전에는 컨텍스트를 교체하지 않습니다.
  HAL에 해제 가능한 객체 포인터를 넘기지 않아 세대별 게이트 누수를 없앴습니다.
- 렌더 진입에서 `thread_local`을 제거했습니다. 새 HAL 스레드에서도 TLS 초기화
  없이 부동소수점 레지스터를 확인합니다.
- `EngineState`가 숫자 형식을, `EngineStateStore`가 파일 I/O를 각각 책임집니다.
  기존 저장 함수는 3411회 읽기 중 빈 상태가 280회 관찰됐습니다.
  새 저장은 완성된 임시 파일을 원자적으로 교체하며, 3000회 쓰기와 동시 읽기에서
  불완전한 상태가 노출되지 않았습니다. 실패 시 기존 파일을 보존합니다.
- 비활성화한 파라메트릭 밴드의 편집값도 저장하며, 잘린 숫자/밴드 데이터는
  부분 적용하지 않습니다. 공간 모드의 비정상 숫자와 범위·정수 검증도 보완했습니다.
- 중복 `outputStarted` 상태를 제거하고 `OutputDevice.running()`을 사용합니다.
  첫 출력 초기화/시작이 실패해도 드라이버 매핑이 있으면 재시도합니다.
  첫 복구 성공은 별도 HELLO 없이 실행 상태로 전환합니다.
- 통합 테스트는 실제 `OutputDevice.cpp`를 모의 HAL에 연결해 돌렸습니다.
  준비 전 호출, 중단·재시작·초기화/시작 실패, 해제 후 지연 호출, 짧은 버퍼를
  검사했습니다. 이는 실기기 검증과 구분합니다.

검사 결과: 최적화 빌드의 네이티브 24/24, Swift 111/111 통과.
분석 전달과 콜백/링 수명주기는 ThreadSanitizer 통과,
콜백/링·모의 HAL·상태 저장은 AddressSanitizer/UndefinedBehaviorSanitizer 통과.

다음 순서로는 앱 편집 상태/저장 분리와 A/B·실행 취소 기능을 먼저 잡습니다.
함께 남은 엔진 제어·장치 감시·볼륨 책임 분리, 실제 프리셋 변경 연속성,
IPC 메시지 길이/버전, Room Tune PCM·취소 경로를 검증합니다.
전체 목표에는 아직 도달하지 못했고 실기기 검증과 배포에도 들어가지 않았습니다.

### 수명주기 보호 추가 후 성능 확인

변경 전 소스와 변경 후 소스를 각각 최적화해 비교했습니다. 이전처럼 두 버전을
한 번씩 일괄 실행했을 때 일부 조건에서 비용 증가가 관찰됐습니다. 실행 순서/

샘플레이트·효과 조건에서 두 버전을 번갈아 측정했습니다. 준비 구간과 7회
중앙값 기준은 유지했습니다.

| 샘플레이트 | 조건 | 이전 ns/프레임 | 변경 ns/프레임 |
|---|---|---:|---:|
| 48kHz | 평탄 | 63.581 | 52.430 |
| 48kHz | 전체 효과 | 224.510 | 200.142 |
| 192kHz | 평탄 | 53.260 | 52.648 |
| 192kHz | 전체 효과 | 226.038 | 212.152 |

있어 개선률을 고정된 값으로 못 박지는 않습니다. 이는 `pullRender` 계산 비용이며
HAL 스케줄링·장치 지연·글리치율은 별도 실기기 측정이 필요합니다.

`build/render-benchmark.csv`에 보존했습니다.

## 2026-09-07 후속 작업: 앱 편집 상태와 A/B

- `SoundSnapshot`이 전체 DSP 설정·매크로·프리셋 식별자를, `SoundEditor`가
  A/B 상태와 각각 100단계의 실행 취소/다시 실행을 관리합니다. 한 드래그 도중
  엔진 응답이 여러 번 와도 하나의 편집으로 묶습니다.
- `ParameterWriter`는 Mach 쓰기를 직렬화하고 대기 중인 최신 요청 하나만
  보관합니다. 연속 드래그가 전송을 무한히 미루지 않도록 제한된 병합 구간을
  사용합니다. 늦은 응답과 폴링 읽기가 새 편집·A/B 전환을 덮어쓰지 않습니다.
- `PresetStore`와 `AppPreferences`로 UserDefaults 접근과 가져오기/내보내기를
  분리했습니다. 기존 저장 키와 JSON 형식은 유지합니다. 잘못된 배열 길이와
  범위를 정규화하고 지원하지 않는 보관 파일 버전은 부분 적용하지 않습니다.

## 2026-09-08 후속 작업: 샘플레이트 변환 품질

- 기존 네 점 Catmull-Rom 보간은 44.1→48kHz의 20kHz 신호를 약 4.44dB
  감쇠시켰습니다. 96→48kHz의 30kHz 신호는 거의 감쇠 없이 18kHz로 접혔습니다.
  단순한 보간만으로는 다운샘플링의 앨리어싱을 막지 못하는 경로를 재현했습니다.
- `SincResampler`를 실제 `RenderPipeline`에 연결했습니다. Kaiser 창(beta 12)과
  낮은 쪽 Nyquist의 95% 컷오프를 사용하며, 다운샘플링 비율에 따라 필터 길이를
  늘립니다. 정수 명목 샘플레이트는 최대공약수로 구한 위상과 정수값 누산으로
  처리해 부동소수점 위치 오차가 누적되지 않게 했습니다. 비정수 샘플레이트는
  위상 표를 보간합니다. 같은 샘플레이트는 필터를 거치지 않는 비트 일치 경로입니다.
- 계수와 이력을 `prepare()`에서만 할당합니다. 작은 scratch 버퍼는 여러 번
  채워 모든 입력 프레임을 소비하며, 0프레임 출력·비정상 샘플·8채널·초기화를
  검사했습니다. 입력 중단/복구와 큰 콜백도 실제 렌더 경로에서 검증했습니다.
  처리 상태 준비에 실패하면 출력 장치를 닫고 기존 재시도 경로로 오류를 반환합니다.
- 총 171개 조건을 검사했습니다. 통과 대역 톤 64개, 정지 대역 톤 11개,
  정지 대역 주파수 격자 3×32개입니다. 44.1/48/96/192/768kHz와 비정수 명목률,
  8kHz 변환을 포함하며 낮은 샘플레이트의 통과 대역은 Nyquist 아래로 제한합니다.
  통과 대역 기준은 0.05dB 이내, 변환 잔여 성분과 앨리어싱은 −100dB 미만입니다.
  측정한 최악의 잔여 성분은 −128.1dB, 앨리어싱은 −123.3dB였으며,
  레벨 오차는 소수점 넷째 자리 출력에서 모두 0.0000dB 범위였습니다.
- 추가 그룹 지연은 임펄스 피크로 확인했습니다. 44.1/48kHz 계열의 일반적인
  변환은 약 2.7~2.92ms이며, 같은 샘플레이트에서는 0입니다. 8kHz와 다른
  샘플레이트 사이의 변환은 약 16ms가 필요합니다. 이는 기존 리미터·장치·링 대기 지연과 별도입니다.
  앱의 현재 지연 표시는 하드웨어 장치 정보이며, 전체 경로 지연의 표시/측정은
  아직 완료하지 않았습니다. 실제 두 장치 사이의 클록 오차 검증도 남아 있습니다.
- 설계 근거는 [Julius O. Smith의 대역 제한 보간 자료](https://www.dsprelated.com/freebooks/pasp/Windowed_Sinc_Interpolation.html)에서 가져왔습니다.
  다운샘플링 시 낮은 샘플레이트에 맞춰 컷오프와 필터 길이를 함께 조정하는
  원칙을 적용했습니다. 기존 `CubicResampler`는 비교 측정용으로 남겨 두었습니다.

### 동일 필터의 SIMD 최적화

Apple Silicon에서는 같은 배정밀도 필터 계수를 NEON으로 처리합니다.
스칼라/SIMD 버전을 번갈아 7회 재서 스레드 CPU 시간의 중앙값을 냈습니다.
512프레임 블록이며 입력 공급과 측정 루프 비용을 포함합니다.

| 입력→출력 | 스칼라 ns/출력 프레임 | SIMD ns/출력 프레임 |
|---|---:|---:|
| 48→48kHz | 2.04 | 2.03 |
| 44.1→48kHz | 234.52 | 145.36 |
| 48→44.1kHz | 265.61 | 176.92 |
| 192→48kHz | 863.16 | 678.15 |
| 768→44.1kHz | 3969.80 | 3513.39 |
| 44.1→768kHz | 277.98 | 186.61 |
| 44100.25→48000.75Hz | 497.37 | 271.42 |

변환 조건의 연산 비용은 동일 필터의 스칼라 구현보다 약 10~45% 줄었습니다.
그러나 긴 저역 통과 필터를 쓰므로 기존 Catmull-Rom보다 계산량이 많습니다.
그래서 기존 알고리즘 대비 전체 성능 향상이라고 쓰지는 않습니다. 일반적인 44.1↔48kHz는
계수/이력 준비에 약 0.3MiB, 768kHz와의 큰 비율 변환은 약 5.2MiB까지 사용했습니다.
높은 샘플레이트의 일부 블록 경과 시간 p99는 주기를 넘었으므로, 실제 HAL의
기한 준수나 글리치율은 이 합성 측정만으로 판단할 수 없습니다.

검사 통과, 렌더 중 C++ 힙 할당 0회. Intel x86_64 대상은 컴파일만 확인했고

  EQ 값과 청취용 레벨 보정을 분리하는 사용 흐름의 참고 자료입니다.
- 12dB 차이의 A/B 전환에서 최대 샘플 차이는 약 2e-9였습니다. 서로 다른 EQ,
  파라메트릭 필터, 공간 처리, 컴프레서를 적용한 두 출력의 가중 에너지 차이는
  약 −0.0003dB였습니다. 실제 `RenderPipeline`의 리샘플링 경로에서도 보정과
  A/B 교환을 검사하면서 200% 출력, 무음, 참조 처리 실패, 우회, 빠른 토글의
  피크 제한과 렌더 중 C++ 힙 할당 0회를 확인했습니다.

### 명령과 상태 경계
